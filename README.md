# 費用管理系統

給主任辦公室用的靜態網頁版費用管理工具。韓系極簡風格，四個經費子項目
（主任月費用／院內計畫／中心零用金／小組聚餐）與研究計畫經費模組，並有
本月與歷年對帳、一鍵下載 PDF 報告的功能。

> ⚠️ **最重要的一件事：資料只認「網址」，不是認「電腦」。**
> 如果你先用「雙擊 html 檔案」的方式在電腦上測試（網址列會是
> `file:///...` 開頭），之後又改用 GitHub Pages 網址
> （`https://你的帳號.github.io/...`）開啟，這兩個在瀏覽器眼中是
> **完全不同、互不相通的兩個地方**，資料不會互相同步，看起來就會像
> 「資料不見了」。請確定之後都只用同一個網址操作（建議直接用
> GitHub Pages 網址），並養成定期按「匯出備份 JSON」的習慣。

---

## 這是什麼樣的系統？（給不熟程式的你）

這是一個「純網頁」小工具，**沒有資料庫、也不需要架伺服器**。所有資料
會存在**你目前使用的瀏覽器裡**（技術上叫 LocalStorage），跟你在這台
電腦、這個瀏覽器打開網站時看到的資料是同一份。

好處：不用學怎麼寫程式、不用每次新增資料就要去改檔案、上傳 GitHub。
需要注意的地方：

- 資料只存在**這台電腦的這個瀏覽器**裡。換一台電腦或清除瀏覽器資料，
  資料就會不見。
- 所以請**定期使用側邊欄最下方的「匯出備份 JSON」**，把資料存成一個
  檔案（例如存到雲端硬碟）。要換電腦或不小心資料不見時，用「匯入備份
  JSON」把檔案讀回來就好。
- 如果之後想讓多台電腦、多個人同時存取同一份資料（例如你和助理都要
  編輯），現在的架構還不支援，需要另外加後端資料庫，屆時可以再請人
  （或再問我）升級。

## 放到 GitHub Pages 上（最簡單的「架在 GitHub」方式）

1. 到 GitHub 開一個新的 repository（可以設成 Private，只有你自己看
   得到 code，但 GitHub Pages 網址本身是公開連結，請不要放病患個資，
   只放經費金額類資料）。
2. 把這個資料夾裡的所有檔案上傳上去（可以直接在 GitHub 網頁上
   「Add file → Upload files」拖曳整個資料夾，不需要用終端機指令）。
3. 進 repository 的 **Settings → Pages**，Source 選擇你上傳的分支
   （通常是 `main`），資料夾選 `/ (root)`，按 Save。
4. 等 1–2 分鐘，GitHub 會給你一個網址，例如：
   `https://你的帳號.github.io/你的repo名稱/`
   之後每次要用，直接開這個網址即可，跟平常開網頁一樣。

> 之後想更新畫面（例如改顏色、改標題），只要把新的檔案再上傳、覆蓋
> 舊檔即可，資料（LocalStorage）不會因此消失。

## 對帳與「沖帳」怎麼運作

新增一筆「主任月費用」項目時，關鍵欄位是**款項性質**，有三種選擇：

- **代轉款項（主任沒有出錢，不需歸還）**：主任只是代為申請、代為轉交
  給中心，錢從頭到尾都不是主任出的，不算欠他的錢。
- **主任先墊付（需要歸還）**：這筆錢是主任自己先掏腰包付的，之後中心
  ／學校／醫院要還給他。選這個之後會多出「已經入帳／歸還給主任」＋
  「入帳月份」欄位。
- **主任支應但不需歸還（主任自行吸收）**：主任自己花了這筆錢，但他
  選擇不用申請歸還（例如自己請客、自己買的小東西）。這種情況不算欠
  款，但又跟「代轉款項」不一樣（代轉是主任根本沒花錢），所以獨立成
  一個選項，方便你清楚記錄「這筆錢主任真的自己出了，只是他不計較」。

只有選「主任先墊付（需要歸還）」的項目，才會被計入「歷年對帳」頁面
的未歸還總額。

**沖帳（金額入帳月份可以跟發生月份不同）**：選「主任先墊付」後，勾選
「已經入帳／歸還給主任」＋指定「入帳月份」——這個月份**可以跟原本
產生費用的月份不一樣**——例如 5 月主任先墊了一筆錢，6 月才匯款歸還，
你只要把這筆 5 月的項目打開編輯、勾選「已入帳」、入帳月份選 6 月，
系統就會自動把這筆算進 6 月的「本月已入帳給主任」，達成跨月沖帳。

「歷年對帳」頁面會列出**所有還沒被標記入帳**的墊款（僅限「主任先墊
付」類型），並提供「標記已入帳」的快速按鈕，方便你事後回去做沖帳，
不用跑回主任月費用頁面找。

## 下載 PDF 報告

每個頁面右上角都有「下載 PDF 報告」按鈕，會直接把目前畫面上的對帳
結果、費用明細轉存成 PDF 檔（不需要用瀏覽器的列印功能，也不需要另外
調整版面設定），適合用來跟主任報告或存檔。

核對、修改，或直接刪除重建。** 如果想清空重來，可以在瀏覽器開發者
工具的 Console 打：

```js
localStorage.removeItem('expenseManagerData_v1')
```

再重新整理頁面即可回到全新狀態。

## 雲端同步設定教學（讓多台裝置的資料同步在一起）

系統預設只用瀏覽器本機儲存。如果你想要「手機輸入、電腦馬上看得到」，
可以照著下面步驟接上一個**免費**的 Google Firebase 帳號，大約 10 分鐘：

1. 前往 https://console.firebase.google.com/ ，用你的 Google 帳號登入。
2. 點「新增專案」，取個名字（例如 `expense-manager`），一路下一步，
   Google Analytics 那步可以關掉不用開。
3. 專案建立完成後，在專案總覽頁點「`</>`」（網頁）圖示，新增一個網頁
   應用程式，取個暱稱即可，**不需要**勾選 Firebase Hosting。
4. 這時畫面會顯示一段 `firebaseConfig = { apiKey: "...", ... }` 的程式碼，
   把大括號 `{ ... }` 裡面**整段**複製起來，等一下會用到。
5. 左側選單點 **Build → Firestore Database → 建立資料庫**，模式選哪個
   都可以（之後會用下面的規則覆蓋），地區建議選離台灣近的
   （例如 `asia-east1`）。
6. 資料庫建立後，切到上方的 **規則（Rules）** 分頁，把裡面的內容整個
   換成：
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /syncRooms/{roomCode} {
         allow read, write: if true;
       }
     }
   }
   ```
   按「發布」。
7. 回到費用管理系統，側邊欄最下面點「**雲端同步設定**」，把第 4 步複製
   的內容貼到「Firebase 設定」欄位，自己取一組「同步房間代碼」（隨便
   一組英數字，只要記得——兩台裝置要輸入完全一樣的代碼才會連在一起），
   按「儲存並連接」。
8. 到第二台裝置（例如手機），打開**同一個網址**，一樣點「雲端同步
   設定」，貼上**一模一樣**的 Firebase 設定＋房間代碼，儲存。兩邊資料
   就會自動同步了；之後其中一台新增/修改資料，另一台重新整理頁面
   （或本來就開著的頁面會自動整理）就會看到最新內容。

> ⚠️ 上面第 6 步的規則是「知道房間代碼的人都能讀寫」，方便非工程師
> 設定，但代表安全性不是很嚴格。建議：房間代碼取長一點、不要公開分享；
> 系統裡也請避免輸入病患姓名、病歷號等敏感個資，只記錄金額／項目
> ／代號這類經費資訊。

不想用雲端同步的話，維持不設定即可，系統會照原本方式運作，資料留在
本機瀏覽器，跟之前完全一樣。
